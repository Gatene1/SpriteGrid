SpriteGrid SpriteSheet File Spec — .gss (Sprite Sheet)
=====================================================

Purpose
-------
A .gss file stores a SpriteGrid “Sprite Sheet”: a grid of fixed-size logical cells,
where each sprite may occupy multiple cells.

SpriteGrid v4 stores .gss as a text format:
  MAGIC | JSON | PAYLOAD

File Type
---------
Extension: .gss
Encoding: UTF-8 text
Line Endings: LF or CRLF (either is fine)

High-Level Layout
-----------------
The file is a single UTF-8 string with 3 sections separated by a single pipe (|):

  <MAGIC> "|" <JSON> "|" <PAYLOAD>

MAGIC
-----
Must be exactly:
  SG4GSS

JSON Section
------------
A JSON object describing the sheet and how to interpret the payload.

Required fields:

1) format (string)
   Must be "GSS".

2) version (number)
   Must be >= 4.

3) meta (object)
   Required keys:
   - createdUtc (string, ISO 8601 UTC)
   - updatedUtc (string, ISO 8601 UTC)

4) sheet (object)
   Required keys:
   - cols       (number)  Sheet width in logical cells (cell = 16x16 sprite pixels)
   - rows       (number)  Sheet height in logical cells
   - cellPx     (number)  Logical cell size in sprite pixels. Must be 16.
   - encoding   (string)  Must be "ABGR32" (SpriteGrid v4 native)
   - packing    (string)  Must be "0xAABBGGRR" (SpriteGrid v4 native)
   - colorParadigm (string) Must be "ABGR" for v4 defaults (future: user-selectable)
   Optional keys (recommended):
   - name       (string)  Display name (no filesystem assumptions)
   - app        (string)  "SpriteGrid"
   - appVersion (string)
   - uiZoom     (number)  UI-only scale factor for display (ex: 1 or 2)
   - notes      (string)

JSON Delimiter Rule
-------------------
Because section delimiters are pipes (|), any JSON string value MUST NOT contain
a raw pipe character. If needed, store a pipe as an escaped unicode sequence:
  "\u007C"

PAYLOAD Section
---------------
The payload stores TWO lists:
1) Sprites (pixel data)
2) Placements (where sprites sit in the sheet grid)

The two lists are pipe-separated and labeled:

  SPRITES:<count>|<sprite0>|...|<spriteN-1>|PLACEMENTS:<count>|<pl0>|...|<plM-1>

SPRITES List
------------
Each sprite record stores pixel data once.

Sprite record format:
  P:<id>:<wPx>:<hPx>:<values>

Where:
- <id>  is a non-negative integer unique within the file.
- <wPx> is sprite width in pixels
- <hPx> is sprite height in pixels
- <values> is a comma-separated list of unsigned 32-bit integers (base-10),
  length MUST equal wPx*hPx.
- Pixel packing is ABGR32 in 0xBBGGRRAA (decimal representation) by default.
  Readers MAY support other paradigms in the future using sheet.colorParadigm.
- 0 means fully transparent (0x00000000).

Example sprite (2x2):
  P:0:2:2:0,4294967295,4294967295,0

PLACEMENTS List
---------------
Each placement record places a sprite onto the sheet cell grid.

Placement record format:
  L:<id>:<xCell>:<yCell>:<wCells>:<hCells>:<rot>

Where:
- <id>      is a sprite id defined in the SPRITES list
- <xCell>   is the sprite's top-left column in sheet cells
- <yCell>   is the sprite's top-left row in sheet cells
- <wCells>  is the sprite's width in sheet cells
- <hCells>  is the sprite's height in sheet cells
- <rot>     is rotation in degrees: 0, 90, 180, 270

Rules:
- Each sprite record represents a physical entry on the sprite sheet.
- A sprite ID may appear at most once in the PLACEMENTS list.
- To duplicate a sprite on the sheet, a new sprite record with a new ID
  must be created (even if pixel data is identical).
- Writers targeting v4 must emit rot = 0.
- Readers should tolerate non-zero rot for forward compatibility.

Rotation Policy (SpriteGrid v4 default)
---------------------------------------
In SpriteGrid v4, rotation is expected to change the sprite pixel data itself.
Therefore writers SHOULD store <rot> as 0 and physically rotate pixel data in the
SPRITES record when the user rotates a sprite.

<rot> is reserved for potential future "placement-only rotation" support.

Occupancy Rules
---------------
- Logical cell size is 16x16 sprite pixels (sheet.cellPx must be 16).
- A sprite occupies:
    wCells = wPx / 16
    hCells = hPx / 16
  Therefore wPx and hPx MUST be multiples of 16 for v4.

- Placements MUST NOT overlap (no two sprites may occupy the same sheet cell).
- Placements MUST be fully in bounds:
    0 <= xCell, yCell
    xCell + wCells <= sheet.cols
    yCell + hCells <= sheet.rows

Validation Rules
----------------
A reader should reject the file if:
- MAGIC is not "SG4GSS"
- JSON cannot be parsed
- JSON.format != "GSS"
- JSON.version < 4
- sheet.cols/rows missing or not positive integers
- sheet.cellPx != 16
- Any sprite record is not "P:id:wPx:hPx:values"
- Any placement record is not "L:id:xCell:yCell:rot"
- values length != wPx*hPx
- Any value is not a valid unsigned 32-bit integer (0..4294967295)
- Any placement refers to a missing sprite id
- Any placement overlaps another placement
- Any placement is out of bounds
- Any wPx or hPx is not divisible by 16

Example
-------
SG4GSS|
{"format":"GSS","version":4,"meta":{"createdUtc":"2026-01-07T00:00:00Z","updatedUtc":"2026-01-07T00:00:00Z"},"sheet":{"cols":10,"rows":6,"cellPx":16,"encoding":"ABGR32","packing":"0xBBGGRRAA","colorParadigm":"BGRA","uiZoom":2,"name":"Example Sheet"}}|
SPRITES:1|
P:0:32:16:0,0,0,0,...|
PLACEMENTS:1|
L:0:0:0:0
