SG4GSS
SpriteGrid Sprite Sheet File Specification v4.0

----------------------------------------
FILE OVERVIEW
----------------------------------------
A .gss file is a custom SpriteGrid sprite sheet container.

It consists of:
1. A magic header
2. A JSON metadata section
3. A structured data-dump payload

This format is intentionally human-readable, versioned, and hand-designed.

----------------------------------------
FILE STRUCTURE (HIGH LEVEL)
----------------------------------------
SG4GSS
{ JSON METADATA }
---
SPRITES
P-records...
PLACEMENTS
L-records...

----------------------------------------
1. MAGIC HEADER
----------------------------------------
SG4GSS

Identifies the file as a SpriteGrid v4 sprite sheet.
Must appear on line 1.
Parser should reject files without this header.

----------------------------------------
2. METADATA SECTION (JSON)
----------------------------------------
Purpose:
- Describe how to interpret the sprite sheet
- Store versioning and descriptive info
- Does NOT contain pixel data

Example:

{
  "type": "spritesheet",
  "name": "Untitled Sheet",
  "createdUtc": 1736559000000,
  "modifiedUtc": 1736560123000,
  "notes": null,
  "gridCellSize": 16,
  "colorParadigm": "ABGR",
  "spriteCount": 12
}

Metadata ends at the first line containing only:
---

----------------------------------------
3. PAYLOAD SECTION
----------------------------------------
Everything after --- is the data dump.

----------------------------------------
3.1 SPRITES SECTION
----------------------------------------
Begins with:
SPRITES

Each sprite is defined by a P-record.

P-RECORD FORMAT:
P:<id>:<wPx>:<hPx>:<createdUtc>:<modifiedUtc>:<pixelData>

Field Definitions:
- id: Unique sprite ID
- wPx: Width in pixels
- hPx: Height in pixels
- createdUtc: Creation timestamp
- modifiedUtc: Last modification timestamp
- pixelData: Comma-separated Uint32 values (ABGR)

Example:
P:3:32:32:1736559000000:1736560123000:0,0,4294967295,...

----------------------------------------
3.2 PLACEMENTS SECTION
----------------------------------------
Begins with:
PLACEMENTS

L-RECORD FORMAT:
L:<spriteId>:<xCell>:<yCell>

Example:
L:3:5:2

----------------------------------------
DERIVED DATA (NOT STORED)
----------------------------------------
The following values are calculated at load time:
- wCells
- hCells

Derived as:
wCells = ceil(wPx / gridCellSize)
hCells = ceil(hPx / gridCellSize)

----------------------------------------
IN-MEMORY SPRITE OBJECT (REFERENCE)
----------------------------------------
This is NOT file format, but the in-editor representation:

spriteIndividualTemplate:
id
name
notes
createdUtc
modifiedUtc
wPx
hPx
pixels (Uint32Array)
xCell
yCell

----------------------------------------
DESIGN PRINCIPLES
----------------------------------------
- Metadata describes; payload contains data
- JSON only where it makes sense
- Pixel data remains a dump
- Format must be inspectable and editable by hand
- Forward-compatible by design
